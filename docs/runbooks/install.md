# Installation

> Phase 7. Server on Linux (x86-64 or ARM64) with systemd, or in a container. CLI on Linux, macOS, and Windows.
> Last updated: 2026-11-17

## 1. Download and verify

Each release publishes binaries, `SHA256SUMS`, and `SHA256SUMS.sigstore.json`: the Sigstore *keyless* signature, made by the repository's release workflow. There is no private key to safeguard.

```bash
VERSION=0.1.0            # without the "v"
TARGET=x86_64-unknown-linux-musl   # or aarch64-unknown-linux-musl
base=https://github.com/Khr0x/onepack/releases/download/v$VERSION
curl -fLO "$base/onepackd-$VERSION-$TARGET.tar.gz"
curl -fLO "$base/SHA256SUMS"
curl -fLO "$base/SHA256SUMS.sigstore.json"

# The signature proves that SHA256SUMS was generated by this repository's release workflow, for that tag.
cosign verify-blob --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "https://github.com/Khr0x/onepack/.github/workflows/release.yml@refs/tags/v$VERSION" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS

tar -xzf "onepackd-$VERSION-$TARGET.tar.gz"
sudo install -m 0755 "onepackd-$VERSION-$TARGET/onepackd" /usr/local/bin/onepackd
```

Linux binaries are static (musl): they do not depend on the glibc version. The CLI (`onepack-…`) is installed the same way on each workstation; on Windows it comes in a `.zip`.

## 2. systemd service

Files: [`packaging/systemd/onepackd.service`](../../packaging/systemd/onepackd.service) and [`packaging/systemd/onepackd.env`](../../packaging/systemd/onepackd.env).

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin onepack
sudo install -d -m 0750 -o root -g onepack /etc/onepack
sudo install -m 0640 -o root -g onepack packaging/systemd/onepackd.env /etc/onepack/onepackd.env
sudo editor /etc/onepack/onepackd.env          # ONEPACK_PUBLIC_URL at minimum
sudo install -m 0644 packaging/systemd/onepackd.service /etc/systemd/system/

sudo install -d -m 0700 -o onepack -g onepack /var/lib/onepack
sudo -u onepack onepackd init --data-dir /var/lib/onepack
sudo systemctl daemon-reload
sudo systemctl enable --now onepackd
curl -fs http://127.0.0.1:8080/readyz
```

The initial administrative credential is left in `/var/lib/onepack/initial-admin-token`. Store it in a secrets manager and delete the file ([guide](../guide-zero-to-ci.md#3-set-up-the-cli-as-administrator)).

The unit:

- runs as the `onepack` user, without capabilities or privilege escalation (`NoNewPrivileges`, `CapabilityBoundingSet=`);
- sees the filesystem read-only except `/var/lib/onepack` (`ProtectSystem=strict`, `StateDirectory`), without `/home` or devices;
- restricts syscalls, socket families, namespaces, and executable memory;
- restarts itself after a failure (`Restart=on-failure`) and, when stopped, finishes in-flight requests (SIGTERM).

`systemd-analyze security onepackd` shows the resulting exposure. CI installs the unit, kills the process with SIGKILL, and checks that it returns to `ready` ([`tests/ops/systemd.sh`](../../tests/ops/systemd.sh)).

## 3. Container

Each release publishes `ghcr.io/khr0x/onepack:vX.Y.Z` for `linux/amd64` and `linux/arm64`, built with the verified binaries from the release. The repository's [`compose.yaml`](../../compose.yaml) is the shortcut for the quick start:

```bash
curl -fsSLO https://raw.githubusercontent.com/Khr0x/onepack/v0.1.0/compose.yaml
docker compose run --rm onepackd init
docker compose up -d
```

To build the image from source, [`packaging/container/Containerfile`](../../packaging/container/Containerfile) uses a static binary on `distroless/static`, unprivileged user 65532, and a `/data` volume:

```bash
docker build -f packaging/container/Containerfile -t onepackd .
docker volume create onepack-data
docker run --rm -v onepack-data:/data onepackd init
docker run -d --name onepackd --restart unless-stopped \
  -p 127.0.0.1:8080:8080 -p 127.0.0.1:9464:9464 \
  -e ONEPACK_PUBLIC_URL=https://packages.example.com \
  -v onepack-data:/data onepackd
```

The release workflow also uses [`Containerfile.release`](../../packaging/container/Containerfile.release), which copies the already-built `onepackd` binaries so Rust is not recompiled inside the image.

The image listens on `0.0.0.0:8080` (API and NuGet) and `0.0.0.0:9464` (metrics and probes): expose that second port only to the internal network. For backup, run `onepackd backup` in another container with the same volume ([backup](backup-restore.md)).

## 4. Reverse proxy and TLS

Examples in [`packaging/proxy/`](../../packaging/proxy/): [Nginx](../../packaging/proxy/nginx.conf) and [Caddy](../../packaging/proxy/Caddyfile). Both:

- terminate TLS and forward **everything** to onepackd, which authenticates and authorizes each request. They never serve the data directory directly ([ADR-018](../../roadmap/adr-mvp.md#adr-018));
- accept bodies up to the maximum package size and stream uploads and downloads without buffering;
- assume `ONEPACK_PUBLIC_URL` equals the public URL and `ONEPACK_IP_RATE_LIMIT=0`, because behind the proxy all requests arrive with its IP. The per-IP limit is applied at the proxy (Nginx) or in the firewall.

CI validates their syntax with the official images ([`tests/ops/proxy-configs.sh`](../../tests/ops/proxy-configs.sh)).
